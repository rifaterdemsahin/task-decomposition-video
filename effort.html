Problems hit along the way

The skill assumes a Mac

Kokoro in Docker, mflux on Apple Silicon, Apple emoji font. None available on this VM.

Kokoro via kokoro-onnx on CPU with the same API; Noto emoji; procedural CPU images.

2 GB of free disk

The intro wrote a PNG per frame (~4 MB each at 1080p), about 1 GB for one intro.

Frames piped straight into ffmpeg; nothing written per frame.

Titles ran into diagrams

Wrapping by character count ignored real glyph widths.

Wrap by measured pixel width with the actual font.

Diamond artefacts in backgrounds

Rotating a gradient left black corners.

Diagonal built from a horizontal and a vertical gradient.

skill.md lost its markdown

Frontmatter mid-file; headings, table, code and checklist flattened.

Rebuilt structure, same content, installed under .claude/skills.

Narration too fast

QA measured 175 words/min against the 140–170 target.

0.3 s pauses at sentence boundaries brought it to 170.6; a 0.5 s pause in the next build clears it.

Anthropic docs moved

Old chain-of-thought URLs now redirect; extended thinking's budget mode is marked legacy.

The doc cites the current pages and mentions adaptive thinking.

No git identity on the VM

The first commit was refused.

Identity passed per command; global config left untouched.

Next time

With the pipeline in place, a new lesson is mostly writing: edit the scene JSON and the diagram data, then run ./build.sh, about 10 minutes of CPU time per build here. The slow parts were one-off setup and two structural rewrites. On the Mac with FLUX images and a GPU, image generation would cost more time per scene but look richer.
